# Security Policy

## Reporting

Use GitHub private vulnerability reporting if it is enabled for this repository. If it is not enabled, open a minimal public issue that says a security report is available, but do not include secrets, exploit details, tokens, or private workspace paths.

## Scope

Security-sensitive reports include authentication bypass, unsafe workspace path traversal, local command execution issues, dependency compromise, and workflows that expose repository tokens.

## Handling

Maintainers should confirm receipt, reproduce the issue in a private branch when needed, rotate any exposed credentials, and publish a fix with a short advisory or release note.
